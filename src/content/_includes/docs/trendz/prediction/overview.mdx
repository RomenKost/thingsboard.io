A **prediction model** in Trendz learns from the telemetry history of a device or asset profile and predicts what comes
next: future values, limit crossings, period totals, or target progress. Predictions return to ThingsBoard as
telemetry and alarms, with no model code to write.

## What you can predict

A prediction model is built for one question. Trendz calls this question the intent, and it decides what the
model shows, what it writes to ThingsBoard, and which alarms it can raise. The four intents read the same history
in four ways. Pick one to see how it works.

## How it works in Trendz

A model is trained once from the history. After that, every scheduled refresh updates its forecasts and alarms.

<ImageGallery images={[
  {
    src: '/src/assets/images/trendz/prediction/prediction-blueprint.svg',
    alt: 'Blueprint of a prediction model across ThingsBoard, Trendz, and the Python executor: a training task reads history, fits the model in the Python executor, and saves it to the Trendz database; a scheduled refresh starts a refresh task that reads new data, loads the model, optionally retrains, predicts through the Python executor, raises alarms, and saves the forecast back to device telemetry, which dashboards and rule chains use',
    caption: 'Training and every refresh, step by step. Follow the numbers from 1 to 12.',
  },
]} />

**What you get in ThingsBoard:**

- **Forecast:** saved on each device or asset as telemetry. Show it on a dashboard next to the real readings.
- **Alarms:** listed with the other alarms of the device or asset. Send them by email or SMS with a rule chain.
